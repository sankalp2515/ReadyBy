# ReadyBy v0.3.0 — checked household recovery over MCP

ReadyBy helps a household recover a shared departure plan after an estimate changes. Completed work is preserved, essentials stay protected, and consequential trade-offs require review. This first public release demonstrates the Alexa+ experience through our own web simulator with a real MCP backend.

## Included

- Official SDK MCP server and browser/independent CLI clients: protocol **2025-11-25**, Streamable HTTP and **13 tools**.
- Real configured Groq/Gemini interpretation, a configurable NVIDIA adapter and local Ollama alternative; quota-aware fallback and actual receipts.
- Deterministic scheduling plus independent verification of dependencies, passive waits, participant capacity and deadlines.
- Exact-proposal review/confirmation, scoped prepared calls, household state, revision checks and idempotent mutations.
- Shared household display, reusable routines, optional local Vosk recognition and transcript review.
- Setup/MCP/architecture/hosting documentation, contribution guidance, CI and recorded evidence.

## Verification

The isolated local source export passed **56 tests**, TypeScript checking and a production build. Independent official-SDK clients verified discovery, recovery and essential-task protection. The selected hosted pipeline passed **30/30 development utterances** at median **1,047 ms**, p95 **3,821 ms**. This small prompt-informed corpus includes validation and is not a general accuracy or latency guarantee; earlier failures are retained. CI runs against the published source on Windows and Linux; see its actual status in Actions.

## Start

```bash
pnpm install --frozen-lockfile
pnpm build
node app-server.mjs
```

Open `http://127.0.0.1:4173/`. Conversation requires your server-side hosted-provider key or installed local Ollama model. Direct controls and `node scripts/mcp-demo.mjs` require no LLM. See the README and `docs/SETUP.md`.

## Scope

Local beta, not native Echo connectivity, production OAuth or a hosted cloud deployment. Human microphone quality, production load and customer demand remain unmeasured. Native access, AWS integration, appliance telemetry and push notifications are not claimed. Hosting on Google Cloud is possible after deployment/storage/authentication work; it is not required for the documented hackathon entry path.

Public source/release publication does not submit the Devpost entry or replace the final public working-demo video. IntentSeal is a separate Open Source contribution candidate and not a ReadyBy runtime integration.
