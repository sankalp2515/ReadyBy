# ReadyBy 0.4 — hosted voice judge beta

A changed household estimate should lead to a checked recovery that people can understand and approve. This release adds a real product landing page, guided scenarios and hands-free conversation on top of ReadyBy's existing MCP and scheduling system.

**Try it:** https://34-10-147-168.sslip.io/

- Choose **Try the live demo → 2 · Washer delay → Start live voice** and allow the microphone.
- Say **“The washer has another fifteen minutes left.”** The actual tools compute full finish 08:28 and a proposed 08:16 recovery for an 08:20 departure.
- Say **“yes”** to open review; press **Approve this revision** to commit. The model cannot silently approve changed commitments.
- Try **3 · Essential stays protected** to see the honest infeasible case.

Gemini Live uses one-use short-lived browser credentials. Permanent keys stay server-side; the voice model sends heard transcripts through the real MCP client, intent validation, planner and independent checker. The public deployment uses an isolated Google Cloud project, HTTPS, persistent SQLite, supervised processes and verified daily backups.

**Validation:** 64 automated tests, typecheck and production build passed. A hosted synthetic speech test exercised actual transcription, MCP initialize/list/call, Groq interpretation, checked recovery, 52 returned audio chunks and explicit confirmation. Approved state survived restart; separate household access was rejected. See [0.4 verification](../READYBY_0_4_VERIFICATION.md).

This is an independent Alexa+ web simulation and a judge beta. Native Echo access, AWS use, device sensing, large-scale capacity and customer adoption are not claimed. The owner separately confirmed actual browser/microphone voice success. Noisy-room quality and the complete recording still need rehearsal; synthetic speech is not that evidence. The retained 0.3 narrated walkthrough is historical and is not presented as a recording of this new voice release.

The source export excludes provider credentials, live household databases, backups, dependencies and model weights.
